Keycloak-Demo · Angular

Dieselben Stufen 1 bis 3 wie im Frontend ohne Framework, hier mit angular-auth-oidc-client. Derselbe Client demo-frontend, derselbe Realm, dasselbe Backend. Stufe 4 und 5 stehen im Vanilla-Frontend — sie zeigen Autorisierung, und die entscheidet das Backend, nicht das Framework.

Stufe 1 — Anmelden

Status: {{ angemeldet().isAuthenticated ? 'angemeldet' : 'nicht angemeldet' }}

Der Umweg über auth-dev.htl-leonding.ac.at ist der Punkt: Diese Anwendung sieht das Kennwort nie. Sie bekommt am Ende ein Token und sonst nichts.

Stufe 2 — was im Token steht

Der Mittelteil eines JWT ist Base64, nicht Verschlüsselung — jeder, der das Token hat, kann ihn lesen. Deshalb steht dort nichts Geheimes, und deshalb ist die Signatur das, was zählt. Prüfen kann sie nur, wer den öffentlichen Schlüssel des Realms holt: das Backend.

Stufe 3 — Aufrufe ans Backend
{{ antwort() }}

Ohne Anmeldung antwortet /api/protected mit 401. Das Token hängt der Interceptor an — aber nur an Adressen aus secureRoutes. Ein Token, das an jeden Host mitgeht, den die App aufruft, ist ein Token, das abfließt.
